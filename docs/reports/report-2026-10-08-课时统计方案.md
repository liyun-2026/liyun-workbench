## 2. 逐条回应

### 2.1 识别：关键是**分两条通路**，不要只有一条

> 你说的「并不是单纯的识别文字」——正是现在的短板。系统现在已有的课表识别（`Schedule.importFile`）是「OCR → 一堆纯文字 → 正则硬拆」，合并单元格一多就散架。这次要换成**理解版面**。

**通路 A（推荐、精确）：Word / Excel 原件 → 直接读表格结构，不靠 OCR**
- docx 的本质是个 zip，里面 `word/document.xml` 的 `<w:tbl>` 就是那张表，行列、合并单元格**都是结构化的**。系统已经引入了 mammoth 来解析 docx（现在只用它抽纯文字，**没用它的表格能力**）—— 这次把它用足。
- 这条通路**准确率接近 100%**，因为不存在"认错字"的问题。
- 你本来就有课表的 Word/Excel 原件，**能传原件就传原件**。

**通路 B（补充）：图片 → OCR + 按坐标重建表格**
- 关键点：Tesseract 识别出来的**每一个词都带坐标**（`bbox: x0,y0,x1,y1`）。
- 把 x 坐标聚类 → 得到「列边界」（周一/周二/…）；把 y 坐标聚类 → 得到「行边界」（节次）。于是散落的字就被还原成 **「周几 × 节次」的格子**。这才是"把课表当课表来识别"。
- 识别前用 canvas 做预处理：灰度 + 放大 1.5~2 倍，明显提升手机照片的识别率。
- **整张图只 OCR 一次**，不是逐个格子 OCR（那样又慢又不准）。

**两者共同的"归一化"层**（这是识别之后真正让它能落库的部分）：
- 星期：`星期一` / `周一` / `礼拜一` / `Mon` / 单字 `一` → 统一成系统认识的周几
- 时间：`8:00-9:40` / `08:00~09:40` / `8:00—9:40` / `第1-2节` → 统一折成**起止分钟数**
- 班名 / 老师名 / 教室 → 跟系统里**已有的名册做模糊匹配**；匹配不上就存原文并**标黄**
- 每个格子带**置信度**；低的在预览表里标黄，**你不点确认就不写库**

> **能力边界我说清楚，不吹**：图片识别做不到 100%，受拍照质量、合并单元格、手写、底纹影响。所以主推原件通路，图片作补充。我不会为了好听而承诺图片 100%。

### 2.2 同步进系统课表：**不用新写"推送给谁"**

系统里学生端和老师端**本来就是读同一张课表**：
- 学生端 `Stu.lessons()` 按**班级名**匹配
- 老师端 `Today.myLessons()` 按**老师工号**匹配

所以**只要把识别结果写进课表，学生和老师下次打开就能看到**，不需要额外开发分发。这也是为什么第 1 条要求能成立。

**写入策略（安全第一）**：

| 规则 | 做法 |
|---|---|
| 落库键 | `日期 + 节次 + 班级 + 老师` |
| 同键 | **更新**（不会重复堆成两份） |
| 不同键 | **新增** |
| 文件里没有的既有课 | **一律不动**（只增不改不删） |
| 写库前 | 先出**预览表**给你确认 |
| 写库时 | 自动**归档当期课表**（复用系统已有的归档机制，可一键还原） |

### 2.3 计算：不慢

- 统计是**纯前端数组运算**：读一张课表 → 按老师分组 → 累加节数与分钟数。几百条记录 **< 1 毫秒**。
- 每节时长 = `下课时间 − 上课时间`（分钟）。节次型的课去查作息时间表，时间字符串型的直接解析。
- 慢的只可能是识别（OCR），已按 2.1 处理：整图只认一次 + 结果缓存（改统计参数不会重跑识别）+ 分阶段进度条。
- 上线时我会给你**实测数字**。

### 2.4 排版

- **系统内预览**：照模板 1:1（列宽/字号/行高/边框全用模板真实值）。已实测：**列宽与 Word 模板误差 ≤ 0.11 个百分点**（图 1、图 2 就是这个还原效果）。
- **超 25 行自动分页**，每页重复表头，标题带「（第 2 页）」。
- 表下加**合计行**：`本周共 N 节 · 合计 X 小时 Y 分`。
- **可选**：折算「标准课时」（比如每 45 分钟 = 1 课时）—— 课时费一般按标准课时结算。**不需要可以关掉。**

### 2.5 导出 PDF —— 已定：**方案 B（系统内置引擎 · 一键下载）**

- 点「导出 PDF」→ **直接下载** `王老师_2026年10月课时表.pdf`，不弹系统打印对话框。
- 做法：把页面上那张**已经排好版的表**整页渲染成高清图，再嵌进 A4 PDF（3 倍分辨率 ≈ 288 DPI，打印完全够用）。
- **关键好处**：用的是**浏览器自己的中文字体**，所以**不需要额外塞字体文件**——这比"内置字体的矢量方案"更省、更不容易出乱码。
- 引擎是 MIT 开源库，**自托管进仓库、只在你点「导出」时才加载**，不按次计费。
- **取舍我说明白**：这样出的 PDF，文字是"图片化"的（不能在 PDF 里选中/搜索），文件略大一些。对**打印用的登记表**没有影响。如果你以后要"能搜索文字的 PDF"，那时才需要塞中文字体（约 3~4MB）——现在不必。

### 2.6 统计口径 —— 已定：**默认按月**

- 标题填「年 / 月」，数据行 = 该月全部课。
- ⚠️ **一个人一个月的课通常超过 25 行**（例如每周 14 节 × 4 周 = 56 行）→ 所以**自动分页是主路径，不是边角情况**：每页重复表头、标题带「（第 N 页）」、最后一页表下加合计行。
- 保留「**按周**」开关（你原话是"本周"）。

### 三轮独立复核揪出并修掉的 6 个真问题
1. 合并单元格**整体左移一天、最后一列静默丢失**（且不报警）
2. `rowspan` 跨过表尾时**凭空造出幽灵行**、同一节课复制成 N 条
3. 表头重复星期列**静默吞列**
4. 列表式课表 **7/7 行丢「星期」**
5. 名字里含「周X」的班级（「周一班」「每周一练」）**认不出来**
6. 黄底行的占位文字最差只有 **2.48:1**，最难看清的恰好是"要你核对"的那些格子
