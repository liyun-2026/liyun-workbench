## F1【P0·阻断】考勤页 700–740px 名单塌陷

**问题**：`#page-att` 在 700–740px，`.rrow` 网格挤成 `28px 16px 84px`，26 个姓名全截成 1 个字，学号只剩「学」，表头竖排折行。

**根因**：`page-att.css` 里 `.attgrid` 在 `min-width:700px` 就出双栏（右栏 `clamp(240px,28%,300px)`），700px 时左栏仅 ~152px；且 `.rrow.head` 的 4 个 span 无类名，`@media (max-width:1099px){ .rrow .slot{display:none} }` 只隐藏行内 `.slot`，**表头第 3 格「今日时段」没被隐藏** → 4 格塞进 3 列 → 折行。

**改法**（`page-att.css` + `att.html`，复用现有 1100 断点，未新增断点）：
1. `.attgrid` 基础改为 **单列 flex column**；**双栏只在 `@media (min-width:1100px)`**（`grid-template-columns:minmax(0,1fr) clamp(240px,28%,300px)`）。
2. 单列顺序 = `.chead` → **横向汇总条** → 名单全宽 → 页尾 `.chapter`。汇总条用 `display:contents` 拆开 `.sumsticky`，让「本节小结」成为 `position:sticky; top:58px` 的吸顶条（`order:-1`），「待批请假」`order:1` 落到名单之后。
3. 横向汇总条**复用 `.sumbox/.sumrow/.ratio/.legend` 类名**，只把排布方向由竖改横（`flex-wrap:wrap`，`h3`+4 个 `sumrow`+`.ratio`+`.legend`+「复制」一行铺开）；**未新造汇总组件**。
4. `<1100`：`.rrow{grid-template-columns:34px minmax(44px,1fr) minmax(74px,96px)}`；`.rrow .slot` 与 **`.rrow.head .h-slot`** 一并 `display:none`；`.who{overflow:visible;white-space:normal}`（不裁切）。
5. `att.html` 表头 span 补类名 `h-idx/h-who/h-slot/h-st`（`id="page-att"` 与既有类语义未动）；「复制小结文案」行内 style 收敛为 `.sumacts` 类（顺带 P2-12）。

# 第二轮整改（G1–G3，2026-10-05 复验后收口）

## G1【P2】空态下汇总条留下 146px 空白

**现象**（验证方 `_verify/shots2/R2_att_700_empty.png`）：班级无学员时，汇总条被 `visibility:hidden` **隐藏但仍在布局里占 122px 高**，`chead` 与插图之间留出 ~146px 空白。

**根因**：`att.html` 的 `toggleEmpty()` 用 `$('.sumsticky').style.visibility = 'hidden'`——只藏不可见，不撤布局盒。

**改法**：
- `att.html`：`toggleEmpty()` 改为给容器挂状态类 `$('.attgrid').classList.toggle('is-empty', show)`（与 `#attEmpty` 显隐**同一个条件**），删掉 `visibility` 那行。
- `page-att.css`：`.attgrid.is-empty .sumsticky{display:none}`（**不是** `visibility`）。`display:none` 作用于容器 → 无论单列（`.sumsticky` 平时是 `display:contents`）还是双栏，整棵子树直接退出布局；**不需要**为「contents」另写一条，也不会波及非空态。
- `≥1100` 空态：`.attgrid.is-empty{grid-template-columns:minmax(0,1fr)}`。

**判断依据（宽屏空态怎么表现，主理人要求我给依据）**：空态是「这一页没有名单」的**完整状态**——右侧小结栏（应到/正常/异常/未登记、占比、待批请假）都是「对名单的汇总」，名单为空时它们没有可汇总的对象，留着只是占位；因此**宽屏空态也收起右栏、把双栏收回单列**，让空态插图与唯一的动作「返回名单」占满整宽，视觉重心集中。这与 F1 单列降级是同一套「空/无数据时不摆空架子」的取舍。

## G2【P2】`_qa.html` 的吸顶判据太弱

**问题**：旧判据 `b1 < b0 && b1 <= tbH + 4` 在**完全不 sticky** 时也可能为真（元素若本就在可视区上方，`b1<b0` 天然成立），只靠另一条 `position` 断言兜着——「碰巧为真」的判据不能作为变异测试的证据。

**改法**（`_qa.html`）：改成**三条必须同时成立**的强判据：
1. `getComputedStyle(bar).position === 'sticky'`；
2. 滚动 `s1` 后 `|rect.top − 设定的 top| ≤ 2`（设定 top = `getComputedStyle(bar).top` 解析值 = 58px）；
3. 再滚 600px 后 `|rect.top 变化| ≤ 0.5`（仍在吸附，未脱离）。
另加一条「滚动确实到位」守卫（`scrollY ≈ 目标`），防止页面滚不动导致 ②③ 退化成恒真。`s1 = min(1200, maxScroll−600)`，对 390–1099 自适应。

**变异自证（主理人要求）**：把 `.sumbox:first-child` 的 `position:sticky` 临时改成 `position:static` → 重跑 `_qa.html`：

```
变异后：PASS=291 FAIL=15
  FAIL | att@390  汇总条 computed position:sticky (实=static)
  FAIL | att@390  滚 1200 后 rect.top 命中吸附位 (实 -943.5 ≈ 设定 58)
  FAIL | att@390  再滚 600 rect.top 不变 (-943.5→-1543.5)
  …（700 / 750 / 900 / 1099 各 3 条，共 15 条全红）
恢复后：sha256 不一致文件 = none（16 文件逐字节一致）
```

即：**去掉 sticky，这条新断言必定变红；恢复后逐字节一致**。测试本身抓得到 bug，不再「碰巧为真」。

## G3【P2】吸顶条形似「渲染断了」

**问题**（验证方 `R2_att_700_scrolled.png`）：吸顶时汇总条底色 `--tint` **与内容区同色**，也没有可辨识的分隔，内容从条下划过时像是页面被切掉一截。

**改法**（`page-att.css`，只改窄窗 `.sumbox:first-child` 的吸顶样式）：`background` 由 `--tint` 改 **`--card`（实底白）**，保留 **`border-bottom:1px solid var(--line)`**，使其读得出是「浮在内容之上的一条」。**未引入新阴影档**（`--sh-1/--sh-2` 留给浮层，吸顶条不是浮层）。
**验收**（`_qa.html`）：吸顶条 computed `background-color = rgb(255,255,255)`（非透明实底）；`border-bottom = 1px rgb(231,227,218)`。
取证图：`previews/16_样张_考勤_700吸顶条.png`（1400×1800）。

**已知（按主理人要求原样保留、只作说明）**：单列下汇总条视觉在上、`≥1100` 下在右，而 DOM 顺序恒为 `roster → sumsticky`——**视觉序 ≠ DOM/Tab 序**，判断为可接受：两种排布里 `roster` 都是主内容、`sumsticky` 都是「对它的汇总」，阅读序与 Tab 序都说得通；为对齐视觉序而重组 DOM 会破坏阅读序与 Tab 序，故**不重排 DOM**。
