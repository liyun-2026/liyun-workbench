# 砺蕴教务系统 · 第二轮：三个「结构创新」方向（D / E / F）

> 版本：v1 · 2026-10-04 · 作者：许清楚（产品经理）
> 承接：第一轮 `01-PRD-视觉升级方案.md`（A/B/C 令牌底座）。本轮是**增量重构**，不从配色切入。
> 已定前提：思源宋体子集（用户拍板）｜端口色 6→3 套｜只做电脑端｜单文件、无构建。

## 0. 结论先行（TL;DR）

| # | 结论 |
|---|---|
| 1 | 用户判「没创新」的根因成立且可证：A/B/C 三版**共享同一套骨架**——侧栏（L249）、卡片（L282）、`.page.on` 两列网格（L953）、`.split` 列表+详情（L935），差异只在 `--gold/--radius/--fs-hero/--dur`（L85/81/105/114）。**骨架不动，气质怎么换都像同一栋房子刷了漆。** |
| 2 | 本轮改从**结构**切入，给 3 个方向，全部覆盖用户全选的 4 个轴（版式/交互/可视化/品牌）。 |
| 3 | **D、E 改骨架**（导航结构 + 页面分区 + 信息顺序都重排）；**F 骨架不动**（侧栏/顶栏/导航位置不变，只重排内容区）。用户说"两种都试"，这三版正好给出一条 A/B 对照线：**D/E 是"重构"，F 是"重排"**。 |
| 4 | 我的判断：**E（点阵控制台）最有戏**——它同时命中"数据可视化"这一轴（一屏看全班），而这恰是当前系统最弱、用户最痛的一点（考勤现在是每人一行 4 个 chip，L5098-5100，一屏看不了几个班）；但**风险最高**（要重新学、色盲可及性）。**F 最稳**（回归成本最低），**D 最有叙事感但适配面最窄**。 |
| 5 | 三版都可落地到现有数据模型，**不需要动 `Store` 结构**：今日页数据来自 `att:<date>` / `night:<date>` / `homework`（L4408-4419）；考勤数据来自 `att:<date>` 的 `{studentId,status,pid}`（L5036/L5042）。这是三版能并行实现的前提。 |

## 1. 根因：为什么 A/B/C 会被判「没有创新」

| 证据 | 说明 |
|---|---|
| 侧栏结构三版都一样：`.side{width:76px}`（L250）→ 200px（L917）→ 236px（L951），HTML 里是 `.side > .brand + .greet + .nav`（L1627-1633） | A/B/C 都保留"左侧垂直导航"，没动 |
| 页面容器三版都一样：`.page{display:none}` / `.page.on{display:flex}`（L274-275）→ ≥1100px 变两列网格（L953-956） | "卡片网格"是共同骨架 |
| 卡片三版都一样：`.card{border-radius:var(--radius);border:1px solid var(--line);box-shadow:var(--shadow);padding:var(--pad)}`（L282-286） | 三版只改了 `--radius/--shadow/--pad` 的**值** |
| 今日页三版都是：hero 卡（L1652）+ 新闻卡（L1661）+ 速览卡（L1669）竖堆 | 信息顺序、呈现方式没变 |
| 考勤页三版都是：筛选条（L1765-1773）+ 学生长列表（`#attBody`，L1775）+ 右侧汇总（L5104） | 操作路径没变 |
| 三版变化项全是**令牌**：`--gold`（L85）、`--radius`（L81）、`--fs-hero`（L105）、`--dur`（L114）、断点（L446/914/935/949/984/994） | 即"换气质不换骨架" |

**结论**：创新必须从"用户一眼看到信息的方式""操作的动作""数据的表达""辨识度"四处改，不能从色板改。

## 2. 三个方向速览

| 维度 | **D 时序 · 一条时间轴** | **E 点阵 · 一屏全班** | **F 册页 · 内容区重排** |
|---|---|---|---|
| 一句话 | 系统是一条"今天"的时间轴，此刻在轴上，事项挂在轴上 | 系统是一个"全班控制台"，一屏看完、点哪改哪 | 系统是一本"册页"，沿一条阅读动线办完今天的事 |
| 骨架 | **改骨架** | **改骨架** | **骨架不动** |
| 核心隐喻 | 时间 / 时刻 | 教室座位 / 全班 | 书本 / 章节 |
| 最强轴 | 版式结构 | 数据可视化 | 品牌与文化感 |
| 配色基底 | 第一轮 **A**（暖金） | 第一轮 **B**（青灰） | 第一轮 **C**（骨白） |
| 适配页数（34 页中） | 少（今日/考勤/课表/晚自习） | 中（考勤/名册/量化/看板） | 多（几乎全部） |
| 上手成本 | 中高（找功能=找轴） | 中（要学点阵操作） | 低（导航没变） |
| 用户对比收益 | 叙事感最强、最"不像后台" | 效率与可视化最强 | 风险最低、最保底 |

## 3. 方向 D「时序 · 一条时间轴」—— ⚠️ 改骨架

### 3.1 方向名 + 一句话产品观

**产品观**：把系统从"一堆待办卡片"变成**一条"今天"的竖直时间轴**——老师打开系统，第一眼看的是"此刻站在一天的哪个位置、接下来是什么、哪些事还没做"，而不是"有哪些卡片"。
（不是气质形容词；它说的是"界面靠时间组织，老师沿时间做事"。）

### 3.2 「今日」页版式方案（替代 hero 卡 + 2 卡 + 新闻列）

| 区 | 内容 | 替代了原来的什么 | 改骨架? |
|---|---|---|---|
| 轴首（Persistent Header） | 倒计时天数做成**一枚大数字 + 一行目标日**，宋体标签；右侧一枚"距下一节还有 X 分钟" | 替代 hero 卡（L1652）+ 常驻编辑框（L1655-1659） | 改骨架 |
| 主轴（竖直时间轴） | 早自习 → 上午 → 下午 → 晚自习 四段刻度；**游标线**压在"现在几点"的位置；每个刻度上挂：课（来自 `schedule`）、打卡窗口（`att_slots`）、作业（`homework.date`）、待办 | 替代"速览 4 行 item"（L4420-4424）——同样的数据，改成**挂在轴上** | 改骨架 |
| 节点交互 | 点节点 → 就地展开（打卡窗口点开=进考勤点阵；作业节点点开=勾选完成） | 替代"跳页再操作" | 骨架内创新 |
| 轴尾 | "今日要闻"新闻（**降级**为轴底一栏，横向一行标题滚动） | 替代整张新闻卡（L1661-1668） | 改骨架 |
| 新闻详情 | 点"要闻"进独立页/抽屉 | 替代 `#newsBody` 卡内 420px 滚动区（L1666） | 骨架内创新 |

**视线动线**：眼睛从轴首大数字 → 沿游标向下 → 停在游标下方第一条"还没做"的节点（这就是"现在该干什么"）。

**导航结构变化（改骨架）**：左侧栏收成 **72px 图标栏**（沿用 L250 的 76px 概念），主区全宽给时间轴；导航项按时间轴分区重排（今日/考勤/课表/晚自习归"今天"，其余归"档案/设置"两组）。

### 3.3 「考勤」页版式方案（替代 筛选条 + 长列表 + 右汇总）

| 区 | 内容 | 替代了原来的什么 | 改骨架? |
|---|---|---|---|
| 顶部时段条 | 上午 / 下午 两个**时段刻度**（来自 `Att.SLOTS()`，L5007），当前时段高亮 | 替代 `#attSlot` 下拉（L1771） | 改骨架 |
| 打卡窗口盘 | 点时段 → 展开该时段的**打卡窗口**：一列"应到 N / 实到 N / 异常 N"刻度 + 学生点阵（复用 §4 的点阵单元，但 D 版点阵只服务"当前时段"） | 替代"筛选条 + 长列表"（L1765-1775、L5085-5102） | 改骨架 |
| 汇总 | 汇总**贴在时段条右侧**，随选中时段实时变 | 替代页底 `#attSum`（L1780/L5104） | 骨架内创新 |
| 请假 / 导出 | 收进"更多"抽屉（轴尾） | 替代两张常驻卡（L1783-1814） | 骨架内创新 |

### 3.4 创新点清单（对四轴逐条）

| 轴 | 本版做法 | 改骨架/骨架内 | 证据（替代的是哪行） |
|---|---|---|---|
| 版式结构 | 时间轴取代卡片堆；游标=当前时刻；事项挂轴 | 改骨架 | 替代 L1652/1661/1669 三卡竖堆、L953 两列网格 |
| 交互方式 | 点轴节点就地展开；键盘流（↑↓ 走节点、Enter 展开） | 骨架内 | 替代"跳页操作" |
| 数据可视化 | 轴=可视化；刻度=时段；游标=now；轴首大数字 | 改骨架 | 新增，替代 L4402 的裸 hero 数字 |
| 品牌与文化感 | 宋体做时辰/节次标头；大数字 + 目标日做"册页天头" | 骨架内 | 复用思源宋体（用户已定） |
| （不做） | **本版不做**：点阵批量、头像网格（那是 E 的活） | — | — |

### 3.5 令牌

- **基底**：沿用第一轮 **A（素笺·暖金）**——时间轴是"温暖日常"的叙事，暖纸底 + 墨 + 古铜金最搭。
- **新配色只提一处**：**游标色**（`--cursor`）。它服务的结构概念是"此刻""现在几点"——必须从暖金里单独拎出一条**高对比的暖赭**（浅色 `#B0602A` / 深色 `#E0955A`），因为它要在浅纸底上"压住"刻度线、且不能和"品牌金 `#B08A4F`"混为一谈（金是装饰，赭是"现在"）。**不新增第二种强调色。**

### 3.6 代价与风险

| 项 | 评估 |
|---|---|
| 老师上手成本 | **中高**：习惯"点侧栏找功能"的人，要先懂"轴"是什么；需要一次 30 秒的引导或"轴/列表"一键切换兜底 |
| 34 页回归成本 | 中：只有 今日/考勤/课表/晚自习 4 页适配时间轴，其余 30 页回落到卡片制 → **双轨并存**，样式维护要两套 |
| 手机端能否落地 | 时间轴**天生适合竖屏**（手机很好落地），但本轮只做电脑端，手机端列入下轮 |
| 数据风险 | 低：轴的数据来自现有 `schedule` / `att:date` / `homework`，不动 `Store` |

## 4. 方向 E「点阵 · 一屏全班」—— ⚠️ 改骨架

### 4.1 方向名 + 一句话产品观

**产品观**：把系统从"逐条列表操作"变成**一块全班控制台**——老师面对的**是一整班人**，不是一个一个的学生；一屏看完，点哪改哪、刷选批量改。
（说的是"界面靠'全班'这个空间组织，老师像在教室里扫一眼"。）

### 4.2 「今日」页版式方案（替代 hero 卡 + 2 卡 + 新闻列）

| 区 | 内容 | 替代了原来的什么 | 改骨架? |
|---|---|---|---|
| 指挥带（Command Bar） | 倒计时天数 + 4 枚实时指标 pill（考勤已登记 / 异常 / 晚自习 / 作业）横排一行 | 替代 hero 卡（L1652）+ 速览 4 行（L4420-4424） | 改骨架 |
| 全班视窗（主区·最大） | **全班点阵**：每生一个小方块，颜色=今天最重状态（`Att.worst()`，L5048）；点格就地改状态 | 替代"卡片"这一容器本身当主角 | 改骨架 |
| 右侧窄条 | "今日时间线"（当天课/时段，只读）+ 要闻一行 | 替代新闻卡（L1661）+ 速览卡 | 改骨架 |
| 班级切换器 | 顶部全局"当前班级"下拉（跨页保持，写 `Store._attCls` 同源） | 新增（现每页各自 `#attCls` L1767 / `#rosterCls` L1689） | 改骨架 |

**视线动线**：先看指挥带四个数（有没有异常）→ 眼睛落到点阵里**有颜色的格子**（谁有事）→ 点格处理。异常"自己会浮出来"，不用一行行读。

### 4.3 「考勤」页版式方案（替代 筛选条 + 长列表 + 右汇总）

| 区 | 内容 | 替代了原来的什么 | 改骨架? |
|---|---|---|---|
| 顶部刻度条 | 正常 / 迟到 / 病假 / 事假 **四段占比条**（可点击筛选） | 替代页底汇总文字（L5104） | 改骨架 |
| **点阵打卡盘**（核心） | 姓名方块网格，每人一格；点格 → 弹 4 状态（循环切状态）；**刷选多格批量设状态**；空格=未登记 | 替代"每人一行 + 4 chip"（L5095-5101） | 改骨架 |
| 筛选 | 压缩成一行 icon + 班级切换器 | 替代 `#attDate/#attCls/#attSlot` 三控件（L1766-1771） | 改骨架 |
| 全时段模式 | 「全部时段」= 点阵每格显示分时段小色块（只读，沿用 L5087 只读语义） | 替代 `all` 分支文字（L5089-5092） | 骨架内 |
| 请假 / 导出 | 右侧"待批"窄栏 + "更多"抽屉 | 替代两张常驻卡（L1783-1814） | 骨架内 |

### 4.4 创新点清单（对四轴逐条）

| 轴 | 本版做法 | 改骨架/骨架内 | 证据（替代的是哪行） |
|---|---|---|---|
| 版式结构 | 主区被"一屏点阵"占据；卡片退为辅助 | 改骨架 | 替代 L275 `.page.on` 的卡片流 |
| 交互方式 | **刷选批量**改状态、点格循环切、键盘流（方向键移焦点 + 1/2/3/4 设状态）、就地编辑 | 改骨架 | 替代 L5099 的逐个 `Att.mark()` |
| 数据可视化 | 点阵盘（heatmap/小倍数）、四段占比条、名册头像网格 | 改骨架 | 新增；替代 L5104 纯文字汇总 |
| 品牌与文化感 | 方块网格=教室座位/艺考课堂的隐喻；宋体大标题「今日考勤」+ 印章式状态标记 | 骨架内 | 复用思源宋体（已定） |
| （不做） | **本版不做**：时间轴（那是 D 的活） | — | — |

### 4.5 令牌

- **基底**：沿用第一轮 **B（青灰·单点缀）**——点阵需要**冷静、低饱和**的底，颜色只用于**编码状态**，不能有暖调干扰。
- **新配色只提一处**：**状态四色（需可编码、色觉障碍可辨）**。它服务的结构概念是"点阵里一格的颜色就是一条信息"——所以这四色必须：① 两两亮度差 ≥ 15%；② 每色**再配一个形状/图标**（圆=正常、三角=迟到、斜杠=病假、方=事假）做冗余编码；③ 全部通过 `color-mix` 从 B 的基色派生，避免新增色相。
  - 正常 `#2F7D5D`｜迟到 `#9A6B14`｜病假 `#3B6EA5`｜事假 `#B23A2E`（浅色）；深色各自提亮一档。

### 4.6 代价与风险

| 项 | 评估 |
|---|---|
| 老师上手成本 | **中**：点阵"点一下就改"直觉性其实很强，但"刷选批量"和"颜色=状态"要教一次；须给"列表视图"兜底 |
| 34 页回归成本 | 中：考勤/名册/量化/看板 4 页最适配；30 个表单页用不上点阵，回落卡片制 |
| 手机端能否落地 | ⚠️ **最难**：一屏点阵在手机上会过密（本轮不做手机端，但它会是手机端的最大障碍） |
| 可及性风险 | ⚠️ **最高**：纯颜色编码对色盲不友好 → 必须"颜色+形状"双编码（见 4.5），否则不达标 |
| 数据风险 | 低：点阵数据来自 `Att.mapDay()`（L5040）/ `Att.worst()`（L5048），不动 `Store` |

## 5. 方向 F「册页 · 内容区重排」—— ✅ 骨架不动

### 5.1 方向名 + 一句话产品观

**产品观**：**不动导航**，只把"内容区"从卡片堆重构成**一本可读的册页**——左侧章节索引 + 右侧单一叙事流；老师沿**一条阅读动线**办完今天的事，界面靠"册页的层级"而不是"卡片的分区"来组织。
（说的是"内容区按书页逻辑重排，导航一律不动"。）

### 5.2 「今日」页版式方案（替代 hero 卡 + 2 卡 + 新闻列）

| 区 | 内容 | 替代了原来的什么 | 改骨架? |
|---|---|---|---|
| 版首（Chapter Opener） | **极大展示数字**（倒计时天数 120px，宋体）+ 宋体大标题「今日 · 距统考」+ 一行副题 | 替代 hero 卡（L1652）+ 卡内 `h2`（L1653） | 骨架内（仅内容区） |
| 横向小节带 | 速览 4 项变成**横向 4 个"小节"**（每节：数字 + 标签 + 一句话），细线分隔，无卡片 | 替代速览卡的 4 行 item（L4420-4424）和 `.card` 容器（L1669） | 骨架内 |
| 页尾 | "今日要闻"作为页尾章节，**保留新闻卡但去卡片化**（去 border/shadow，改细线分隔） | 替代新闻卡（L1661-1668） | 骨架内 |
| 就地编辑 | 倒计时点数字直接改（input 只在聚焦时现身） | 替代常驻编辑框（L1655-1659） | 骨架内 |

**视线动线**：一条竖向单栏叙事——大数字 → 大标题 → 小节带 → 要闻；眼睛一路向下，不需要在卡片间跳。

### 5.3 「考勤」页版式方案（替代 筛选条 + 长列表 + 右汇总）

| 区 | 内容 | 替代了原来的什么 | 改骨架? |
|---|---|---|---|
| 章节头 | 班级 + 日期 + 时段做成一行**宋体章节头**，筛选收进章节头的下拉 | 替代独立筛选行（L1765-1773） | 骨架内（仅内容区） |
| 名册页（主区） | 每人一行，但用**细线分栏 + 印章式状态**（不是 4 个 chip）：点印章直接改，改完盖一枚新章 | 替代 `.item + 4 chip`（L5095-5101） | 骨架内 |
| 右侧固定栏 | "本节小结" **sticky 在右**（应到/实到/异常/占比条） | 替代页底 `#attSum`（L1780/5104） | 骨架内 |
| 请假 / 导出 | 页尾章节（去卡片化） | 替代两张常驻卡（L1783-1814） | 骨架内 |

## 7. 三版横向对比与推荐

| 对比项 | D 时序 | E 点阵 | F 册页 |
|---|---|---|---|
| 一句话收益 | 最"不像后台"，时间感强 | 效率最高、"一屏看全班" | 最保底、风险最低 |
| 对标用户痛点 | "今天该干嘛" | "一屏看全班"（用户最痛） | "一眼看清层级" |
| 34 页可复用性 | 低（4 页） | 中（4 页） | **高（几乎全部）** |
| 上手成本 | 中高 | 中 | **低** |
| 可及性风险 | 低 | **高**（须颜色+形状双编码） | 低 |
| 手机端难度 | 低 | **高** | 低 |
| 实施工作量 | 中 | 高 | 中 |

**我的推荐：E 最有戏，F 最保底，D 夹在中间。**
理由：用户明确把"数据可视化"列为全选轴之一，而当前系统**最缺的就是它**——考勤是"每人一行读 4 个 chip"（L5095-5101），根本看不了全班；E 的"一屏点阵"直接命中这条最痛的痛点，也是三版里唯一能产生"这家系统跟别家不一样"观感的方向。
但建议**给用户一个组合选项**：**F 的骨架（稳）+ E 的考勤点阵（锐）**——即"导航和大多数页走 F，但考勤/名册/量化三页用 E 的点阵"。这样既拿到创新的锐度，又不动 34 页的回归面。
