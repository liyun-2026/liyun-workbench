## 一、关键转折：把"读的人"换一下，整件事就通了

之前两版方案都卡在同一个地方，原因是**我默认"学生用自己的手机去碰标签"**：

| | 学生手机碰标签 | 学生拿标签碰刷卡点 |
|---|---|---|
| iPhone 能不能用 | ❌ 完全不能（iOS 至今不支持网页 NFC） | ✅ 无关，学生根本不用手机 |
| 手机没电/没流量 | ❌ 打不了 | ✅ 无关 |
| 微信里打不开 | ❌ 打不了 | ✅ 无关 |
| 学生嫌麻烦不打 | ❌ 打不了 | ✅ 走近放一下就走 |
| 人到底在不在现场 | ❌ 人在宿舍也能打 | ✅ 必须到刷卡点，物理约束成立 |
| 需要多少硬件 | 学生手机（不可控） | **一台设备**（完全可控） |

**所以正确做法是反过来：标签跟着学生走，读卡器固定在教室门口。**

这一换，四个老大难同时消失：iPhone 限制、手机状态、作弊地利（人在宿舍）、设备不可控。

剩下的唯一要求是：**刷卡点那台设备是安卓的，或者是一台开着网页的电脑。**

## 三、标签里写什么：三层防伪，成本却是同一枚标签

这是这套方案的灵魂。同一枚 ¥0.35 的标签，写入方式不同，防伪强度差很多。

### L0　什么都不写，只认 UID（最弱）

读卡器读出标签出厂编号 → 服务端查"这个编号绑定了谁" → 打卡。

- 优点：最简单，电脑读卡器也能跑
- 风险：UID 可以被"可改 UID 的魔改卡"克隆（淘宝 ¥5 有售），借卡代打挡不住
- 适用：只作为电脑读卡器路线的降级模式

### L1　写入签名数据（推荐底线）

教务用安卓手机给每张标签写入一段内容：

```
LY1|2023017|5|K7M2XQ9P
    学号    序号  签名
```

签名 = `HMAC-SHA256(服务端密钥, 学号 + 序号)` 取前 8 位。密钥只在服务端，**学生不知道，所以伪造不出来**。

- ✅ 挡住"自己造一张卡"（造不出签名）
- ✅ **顺带解决了 UID 重复的坑**：我们认的是写入的学号，不是出厂编号，所以就算买到 UID 重复的仿制芯片也照样能用（这是上一版方案里的一条硬风险，直接被绕过去了）
- ⚠️ 挡不住"整段复制"：用 NFC Tools App 把整张标签复制一份，复制品也能过

### L2　滚动码（最强，成本一分不涨）★推荐

**每次打卡成功后，刷卡端顺手把新序号写回标签。**

```
刷之前：  LY1|2023017|5|K7M2XQ9P
服务端校验通过 → 打卡成功
刷之后：  LY1|2023017|6|R3T8WZ2C   ← 当场改写
```

于是：

- 有人复制了你的标签（序号 5）→ 你下一次真实打卡把标签改成了 6 → **他手里的复制品当场作废**
- 服务端同时接受「当前序号」和「上一个序号」两个值（防止写入失败导致卡死），并记录每个序号用了几次
- **同一个序号被用第二次 → 立刻判定"该标签疑似被复制"**，教务端标红，可一键查是谁、什么时候
- 复制卡最多成功一次就被抓到，且留下记录

> 这一套正是 NTAG 424 DNA（带滚动签名的加密芯片，¥10–20/枚）才有的防伪能力，
> 我们**用软件在 ¥0.35 的普通标签上实现了**，成本是它的 1/40。
> 代价只有一条：每次刷卡要多一次写操作，学生**听到"嘀"一声再拿开**（约 1 秒）。

### 三层的取舍

| | 防伪造 | 防复制 | 需要刷卡端能写 | 电脑读卡器能用 |
|---|---|---|---|---|
| L0 UID | ❌ | ❌ | 不需要 | ✅ |
| L1 签名 | ✅ | ❌ | 需要一次 | ❌ |
| **L2 滚动码** | ✅ | ✅ | 需要每次 | ❌ |

**结论：刷卡端用安卓手机 → 上 L2；只能接电脑 → 退到 L0，靠"卡丢了能挂失 + 异常可查"兜底。**

### 为什么不设标签密码？

NTAG213 支持设 32 位密码防止别人改写——但设了密码之后，网页 NFC 就**写不进去了**（浏览器接口没有密码参数），滚动码直接失效。

所以二选一：设密码（防改写但废掉滚动码）／不设密码（靠滚动码 + 服务端克隆检测）。
**选后者**——因为整段复制有服务端兜着，伪造有签名挡着，两条路都堵上了。

## 四、完整链路（学生视角只有一步）

```
【一次性】发卡
  教务端「发卡」页 → 选学生 → 拿空白标签贴到手机背面 → 写入 LY1|学号|1|签名 → 服务端记下绑定
  （单人约 5 秒，80 人约 7 分钟）

【每天】打卡
  学生走到刷卡点，把学员证/卡片往手机上一放（约 1 秒）
      │
      ├─ 刷卡台读到标签（100ms）
      ├─ 送服务端：校验签名 → 查学号是谁 → 按课表判定本节次 → 判迟到几分钟
      ├─ 服务端返回：张三 · 高二1班 · 第2节 · 正常（+ 下一个序号与签名）
      ├─ 刷卡台把新序号写回标签（300ms）—— L2 滚动码
      └─ 屏幕大字显示名字 + 语音播报 + 今日已刷 38/42
```

**耗时**：本地网络 <1 秒 / 跨境约 1.5–2 秒（后端在国外节点，实测单向 0.9 秒）。
80 人排队约 2.5 分钟，早功前 15 分钟绰绰有余；觉得慢就**放两个刷卡点**（两台安卓手机并行），降到 1.3 分钟。

## 五、刷卡台页面长什么样（软件这半边）

教务端新增一页「**刷卡台**」，全屏设计，挂在刷卡点那台设备上：

- 上半屏：**超大字**显示刚刷的人（名字 + 班级 + 节次 + 正常/迟到 X 分钟），配语音播报
- 下半屏：今日已刷计数「38 / 42」+ 最近 10 条滚动
- 顶部：当前节次、时间、网络状态；断网时显示「待核 3 条，联网自动补传」
- 常亮防休眠 + 屏幕不锁 + 断网可打
- 同一页可切到「发卡 / 挂失 / 补卡」

配套还要做：

| 功能 | 说明 |
|---|---|
| 发卡绑定 | 选学生 → 贴标签 → 写入 → 完成，可批量 |
| 挂失 / 补卡 | 丢卡即时挂失（旧标签立刻失效），补一张新标签写新序号，历史记录不受影响 |
| 来源标记 | 考勤记录标 `刷卡 / 手机码 / 待核`，教务端可筛可查 |
| 克隆告警 | 同一序号被用两次 → 标红，列出时间、是谁 |
| 断网待核 | 刷卡台本地缓存密钥，断网也能校验并排队，联网自动补传（补传按收到时间判迟到） |
| 巡检联动 | 巡检页加一项：刷卡台 10 分钟无心跳 → 提示"刷卡台还开着吗" |

## 六、会出什么问题，怎么解

| 问题 | 解法 |
|---|---|
| 安卓手机被电话/通知打断 | 刷卡的那台开飞行模式 + WiFi，只留我们这一个页面 |
| 屏幕休眠 / 学生乱动手机 | 网页常亮锁（Wake Lock）+ 插电 + 放桌面固定位置，桌面贴一张"卡片放这里"的定位贴 |
| 读卡位置找不到（NFC 在手机背面） | 手机**平放桌面屏幕朝上**，贴定位贴；第一次使用带着学生认一次位置 |
| 标签丢了 | 挂失即时生效；补卡 ¥0.35–1.5 |
| 借卡给别人代打 | L2 滚动码让复制品当场作废；真借卡（本人不来、卡给同学）靠"刷卡点有老师看着 + 值班老师可手工标记"管住 |
| 排长队 | 两个刷卡点并行；或错峰（早功/第一节各设一个时间窗） |
| 断网 | 本地校验 + 待核排队 + 联网补传，学生当场就能看到自己名字，不会白刷 |
| 标签贴在金属上读不出 | 别贴金属门框/金属手机壳内侧；贴学员证、PVC 卡、书包挂件都行 |
| 学生把标签撕下来贴手机壳里 | 允许，但要在发卡时说明"贴手机壳内侧可能读不出"，推荐贴学员证 |
| 80 人同时写坏标签 | 理论寿命 10 万次写入，每天 2 次可用 130 年，不用考虑 |
| 教务自己没有安卓手机 | 借一台旧的专门当刷卡台（¥100–200 二手），或走电脑读卡器路线（退到 L0） |

```
   - 安卓手机：¥0（系统版本别太老，Android 8+ / Chrome 89+）
   - 或者：13.56MHz 免驱仿键盘读卡器 ¥25（接电脑，只能跑 L0）

3. 可选：手机支架 / 桌面定位贴 ¥0–20
```

### 三个坑，买错就白花钱

1. **必须 NTAG213（或 215/216），不能是 MIFARE Classic** —— Classic 是另一种协议，很多手机读不了，写入还要破解密钥
2. **必须 13.56MHz**，别买成 125kHz 的 ID 卡 —— 两者不通用，手机根本读不到
3. **别买"可改 UID 的魔改卡"** —— 那种卡是给人克隆用的，买了等于自己给自己留后门（问商家"UID 是否出厂固化"）

> 好消息：因为 L1/L2 认的是"写入的学号 + 签名"而不是出厂编号，
> **UID 重复这个坑对我们的方案基本无影响**；上面第 1、2 条才是真正的红线。
